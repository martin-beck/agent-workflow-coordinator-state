## Objective

Make the `stage` phase reachable only as a read-only, identity-bound artifact
verification operation. The capability may validate a prepared runtime tree,
manifest, digest, ownership, permissions, and source binding, but it must not
replace a runtime, mutate authority state, publish a selector, or authorize
commit, apply, or rollback.

## Acceptance evidence

- The stage capability is constructed only from immutable session identity and a
  generated operation record bound to the same operation, target, backend, and
  fencing token.
- Missing, stale, forged, symlinked, replaced, foreign, malformed, or ambiguous
  artifacts reject before any authority effect and leave the coordinator
  write-closed and usable.
- Git and SQLite artifact checks are explicit where their identity semantics
  differ; no path-only identity is accepted.
- `UpgradeEngine` invokes the capability exactly once for `stage`, records only
  verified non-mutating evidence, and retains fail-closed behavior for all
  unsupported phases.
- Hostile replacement, process-death/uncertain-read classification, contract,
  formal mapping, full coverage, exact-head hosted gates, post-merge Verify,
  and durable state reconciliation are recorded.

## Non-goals

Runtime replacement, selector publication, commit, apply, rollback, release
publication, and any claim of complete Python/TLA refinement remain disabled.
