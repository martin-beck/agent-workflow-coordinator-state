This P0 successor is authorized from GitHub issue #27 and is a prerequisite for enabling
any mutating upgrade command. It must preserve a functional coordinator at every externally
observable boundary and must fail closed whenever barrier state, fencing, or recovery is uncertain.

Source provenance: https://github.com/martin-beck/agent-workflow-coordinator/issues/27

The implementation must provide a project-scoped target-neutral barrier with immutable session
identity and strict CAS transitions `absent -> held -> releasing -> released`; process death,
stale ownership, invalid revisions, digest mismatches, lock timeouts, or incomplete durability
must enter durable `ambiguous` safe mode. Forward and failure-rollback child operations must bind
to the same continuously held barrier and must never release it between failure and rollback.

All authority writes, migrations, command-result appends, observation updates, and mutating
reconciliation must acquire repository-common, control-store, then authority locks in that order,
read and verify the durable barrier before opening the authority transaction, and reject writes
with one stable error while the barrier is `held`, `releasing`, or `ambiguous`. Existing installs
without the compatibility marker remain usable but cannot start an upgrade; missing, corrupt,
aliased, or incompatible control stores fail closed after provisioning.

Acceptance requires public-boundary and independent-process tests for acquire-before-admit ordering,
stale CAS/fence/owner/revision rejection, competing attempts, in-flight drain, every SQLite
mutation route, control DB and WAL/SHM swaps, lock timeout/re-entry, and process death at every
durability boundary. Writes may resume only after independently verified `released`. Bind exact
implementation HEAD, tests, and storage/upgrade TLA+ refinement evidence; do not claim beyond the
tested model or implementation boundary. Git upgrade execution remains fail-closed until this
contract and its independent review are complete.
