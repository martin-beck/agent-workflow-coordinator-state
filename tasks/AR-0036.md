## Objective

Implement the same narrowly bounded generated `backend.backup` operation for Git without reusing SQLite assumptions. The Git adapter must own repository lifecycle identity, backup destination binding, and verification; stage/commit/rollback/dispatch remain rejected.

## Acceptance evidence

- Strict generated operation schema and backend binding reject foreign, stale, malformed, replayed, or unsupported operations.
- Backup is performed only under the existing lock/session/admission seam; repository branch/head and artifact identity are reread before and after the effect.
- Process death, clean-tree failure, destination swap, verifier failure, and uncertain durable outcome all fail closed without changing the selected runtime.
- Focused hostile tests, formal bounded correspondence, AWQ/scope, exact-head hosted gates, trusted post-merge Verify, and state reconciliation pass.
