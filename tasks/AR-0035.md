## Objective

Enable exactly one generated backup operation after validated barrier/session identity, authority binding, and durable operation admission. The operation must leave the running coordinator and selected runtime unchanged and must fail closed on every uncertain boundary.

## Explicit non-goals

Do not enable stage, replacement, commit, validate, reopen, rollback, release publication, or worker dispatch. Git and SQLite authority semantics remain separate.

- Generated opcode and durable outcome schema are pinned to AR-0032/0033 chain records.
- Pre-effect and post-effect identity/fence rereads are mandatory; process death before/during/after backup is classified without claiming success.
- Existing runtime remains functional and selected for every failure path; backup corruption or ambiguity leaves mutation closed.
- Hostile Git and SQLite tests, subprocess/process-death tests, bounded formal correspondence, AWQ, scope, exact-head PR gates, trusted post-merge Verify, and state reconciliation are green.
