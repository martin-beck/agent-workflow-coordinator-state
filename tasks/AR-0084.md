## Problem statement

The current Coordinator vendor manifest is not closed over the runtime used by
`formal/handoffctl/verify.sh`. In particular, `tools/tlc_runner.py` is executed
by the formal verification path but is absent from `tools/vendor.py`'s
`SOURCE_FILES`. A clean consumer sync therefore cannot run the supplied formal
verification path without reaching outside the vendored tree or manually
copying a file. That blocks asb-tui AR-1722 even though its local supersession
model tests pass.

Historical AR-0015 and merged work repaired this class of defect, but the
current upstream main and current vendor output must be treated as the source
of truth. Do not rewrite AR-0015 or cherry-pick an obsolete manifest wholesale:
the allowlist has evolved since the earlier change.

## Required implementation

- Starting from the current exact upstream `main`, compute the transitive set
  of first-party files executed, imported, sourced, or hashed by every tier of
  `formal/handoffctl/verify.sh`.
- Add every missing member of that closure to the maintained allowlist in
  `tools/vendor.py`. The minimum known omission is `tools/tlc_runner.py`;
  preserve all newer entries already present on current main.
- Include the focused tests needed to exercise the vendored formal path. The
  prior candidate's additions to examine against current main are
  `tests/test_tlc_runner.py`, `tests/test_upgrade_commands.py`, and
  `tests/test_upgrade_contract_runtime.py`; include them only where current
  dependency analysis confirms they belong to the closure.
- Keep vendor order and manifest output deterministic. Preserve atomic sync,
  profile/binding isolation, source headers, licenses, hashes, and offline
  behavior. Do not patch any downstream `vendor/` tree by hand.
- Add a regression test derived from the verifier entry point, not merely a
  hard-coded assertion for one filename. It must fail when an executed or
  hashed first-party formal helper is omitted and must cover
  `tools/tlc_runner.py` explicitly.
- Add a clean-room sync test which vendors from the candidate Coordinator tree
  into an empty destination and runs the applicable formal smoke/verification
  path with no fallback to the source checkout.

## Acceptance evidence

1. Source/header/license, Ruff format/lint, mypy, unit, branch-coverage, vendor
   determinism, and applicable formal verification gates pass at the exact PR
   head.
2. A clean vendor sync contains `tools/tlc_runner.py` and all other computed
   closure members with manifest hashes matching their bytes.
3. The vendored verifier runs from the clean destination while the source
   checkout is unavailable, proving that no undeclared fallback is involved.
4. Existing profile, binding, upgrade, and atomic-failure tests remain green;
   hostile missing/substituted helper fixtures fail closed with bounded errors.
5. A separate worker reviews the exact candidate commit and tree. The PR is
   merged only after that review and required functional CI succeed, followed
   by exact post-merge CI verification and durable state reconciliation.
6. For this development repair, unavailable authentication, release signing,
   DCO enforcement, or production publication is recorded as a warning and is
   not a blocker. Exact immutable commit/tree IDs, content digests, peer review,
   tests, and CI remain mandatory correctness evidence.
