## Problem statement

The documented and formal transition contract says an unowned task may move
from `blocked` to `open` after its external blocker is independently cleared
and the exact current revision is supplied. The current implementation instead
requires every `resume` call to name a session record whose trigger is exactly
`pause`. A task released with `release --status blocked` has no such pause
snapshot and can therefore enter a durable state from which no supported
lifecycle command can reopen it.

This was reproduced by downstream asb-tui AR-1575 at task revision 74 after
its external dependency AR-1725 completed. `promote` correctly rejects the
task because it is not `planned`; `claim` correctly rejects it because it is
not `open`; and `resume --session AR-1575@74` fails because no pause snapshot
exists. An older in-progress/update record must not be misrepresented as a
paused snapshot merely to bypass the guard.

## Required implementation

- Define an explicit, machine-checkable distinction between a task paused for
  session restoration and a task released as blocked on an external condition.
- Provide one supported exact-revision transition from externally blocked and
  unowned to open. This may be an explicit `unblock` command or a carefully
  specified session-free `resume` form; preserve the existing exact pause
  snapshot restoration semantics for genuinely paused tasks.
- Preserve the current task's `next_action` for external unblock. A pause
  resume may restore the bound snapshot only when its task ID, revision,
  trigger, status, and integrity checks match.
- Reject stale revisions, active ownership/leases, wrong task/session IDs,
  malformed or ambiguous provenance, paused tasks presented as externally
  blocked, and external-blocked tasks presented with unrelated pause records.
- Implement equivalent Git and SQLite authority behavior, including atomic
  task/projection updates, rollback on injected pre-commit failure, revision
  monotonicity, publication recovery, and deterministic session/audit records.
- Update CLI help and the embedded project guide so operators can select the
  correct transition without inventing state or editing task Markdown.
- Update the lifecycle TLA+ model and its checked properties to distinguish
  pause restoration from external unblock while retaining ownership,
  dependency, CAS, single-linearization-point, and rejection-without-mutation
  invariants.
- Add the repaired runtime and all required tests/docs/formal inputs to the
  official vendor closure. Downstreams must consume it only through an
  official release or exact development sync; never patch a vendored copy.

## Acceptance evidence

1. A focused regression reproduces `claim -> release --status blocked ->
   external blocker cleared -> supported reopen -> claim` on Git and SQLite.
2. Existing `pause -> resume --session` behavior remains byte-for-byte and
   state-machine compatible, including crash/rollback and stale-session cases.
3. Cross-mode hostile tests fail closed and prove rejected calls leave task,
   revision, owner, lease, sessions, projections, and publication state
   unchanged.
4. Concurrent exact-revision reopen attempts admit at most one winner on each
   backend, and a second actor observes a stale/state error without mutation.
5. Source headers, Ruff formatting/lint, mypy, full unit/branch coverage,
   migration/doctor/vendor tests, and PR-publication formal tiers pass at the
   exact reviewed head.
6. A separate worker reviews the exact commit/tree. The reviewed PR merges
   only after required CI is green, followed by exact-main Verify and Formal
   validation and durable coordinator-state reconciliation.
7. A clean downstream development sync proves the repaired command can reopen
   an actual release-blocked fixture without private state or hand edits.

Development authentication, cryptographic signing, DCO enforcement, and
release publication are warning-only for this repair. Exact content identity,
functional tests, independent review, merge identity, and post-merge CI remain
required.
