## Required repair

- Add an explicit `bind-spec` lifecycle mutation accepting task ID, owner, exact
  expected revision, safe relative spec path, and expected spec revision.
- Admit it only for an `in_progress` task with a live matching lease and absent
  `spec_ref`, `spec_revision`, and `spec_acceptance`; reject stale, wrong-owner,
  terminal, expired, partial, rebinding, unsafe-path, missing, malformed, or
  revision-mismatched specifications without mutation.
- Require the referenced tracked JSON task spec to validate under the existing
  policy and match its self-declared reference/revision. Bind before acceptance;
  normal `accept` remains the only operation that records evidence.
- Preserve Git/SQLite parity, atomic revision behavior, generated projections,
  snapshots, migrations, rollback, doctor, privacy checks, formal lifecycle
  guidance, and backward compatibility for already-bound tasks.
- Add hostile tests proving no direct task-record edit is required or accepted
  as an alternative and document the legacy completion sequence.

## Acceptance

The exact candidate requires focused and full Coordinator tests, static and
schema checks, applicable formal tiers, independent exact-head review, hosted
CI and post-merge verification. Vendor the immutable development receipt into
Coordinator-state, use the new mutation to bind AR-0089 to its tracked spec,
then perform ordinary `accept` and `release --status done`.
