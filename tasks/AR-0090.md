## Problem statement

Coordinator task titles are useful but often sentence-length. During concurrent
operations an operator repeatedly sees only an AR identifier or must scan a
long status page to recover the task's purpose. A compact, durable title beside
the identifier would make claims, runs, handoffs, reviews and release checks
easier to follow without replacing the full task title or summary.

## Required outcome

- Add a `short_title` task-record field with a precise, deterministic maximum
  of four human-readable words; reject empty, control-character, multiline,
  over-length, and privacy-unsafe values.
- Provide a compatibility and migration path for existing task records. Do not
  silently derive or mutate persisted titles during a read; migrations must be
  reviewable and fail closed when a record lacks a valid title after the
  declared compatibility window.
- Render `AR-#### — short title` in the default human-readable output for an
  active task, including claim, heartbeat, update, accept, release, `run`,
  snapshot, status, board and recovery paths. Equivalent JSON must retain the
  distinct identifier and `short_title` fields.
- Preserve machine-readable contracts, backend parity, generated projections,
  privacy scanning, task revision/CAS fencing and offline vendoring.
- Add focused positive, migration, hostile-input and both-backend tests. Extend
  formal documentation only if the field changes an abstract lifecycle state.

## Acceptance

The new title is navigational metadata only: it must not alter ownership,
dependency, release, or mutation admission. It must pass the complete
Coordinator gates and receive the ordinary signed+DCO, exact-main, and vendor
handoff treatment for the next release.
