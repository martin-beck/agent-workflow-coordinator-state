Exact downstream adoption of Coordinator development commit
`e863b57edc7f7a21b2aff2c7b45ce226e12637d2` exposed two integration defects.
ASB's existing specs use the additional evidence classes `hosted`, `offline`,
`privacy`, `journey`, and `quality`; the vendored validator replaces that
project vocabulary with its five built-in classes, so render, doctor, and
every lifecycle preflight fail. Separately, exact upstream test fixtures
contain session-shaped UUID literals that are valid test data but are rejected
by ASB's stricter privacy scan.

This AR adds a bounded upstream extension contract rather than authorizing
downstream vendor patches. Default Coordinator behavior stays unchanged. A
project may opt into a strictly validated additive evidence vocabulary through
tracked project policy, and upstream fixtures must remain test-equivalent
without embedding privacy-scanner-shaped literal identifiers. The official
development vendor closure and downstream handoff must include the complete
implementation, tests, schemas, documentation, and formal/runtime identity.

Development authentication, release signing, tagging, and production
verification are warning-only. Exact source/vendor identity, functional
correctness, independent review, signed+DCO commits, hosted CI, merge identity,
and post-merge verification remain required.
