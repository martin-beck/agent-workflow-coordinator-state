## Problem statement

Downstream ASB task AR-1652 is a dependency-ready legacy task whose authoritative
record has empty `branch` and `worktree_key` fields. Coordinator v0.3.57 permits
the task to be claimed, but `handoffctl run` correctly rejects any invocation
from a product checkout with `active task lacks declared worktree and branch`.
Neither `claim` nor `update` exposes a supported way to populate those fields.

The operator must not repair this by editing authoritative task Markdown,
manufacturing a checkpoint, invoking product mutations from the state checkout
with `git -C`, or weakening `assert_invocation_worktree`. The same gap affects
other historical tasks created before the current worktree fence and prevents
their otherwise valid implementation or qualification.

## Required repair

- Add one explicit lifecycle mutation, for example `bind-worktree`, that accepts
  a task ID, owner, exact expected revision, branch, and worktree key.
- Admit it only for an `in_progress` task with a live matching owner lease and
  both existing fields empty. Reject open/planned/blocked/done tasks, expired or
  wrong owners, partially populated metadata, rebinding, stale revisions, and
  duplicate active branch/worktree identities before mutation.
- Validate the branch and worktree key with the same bounded grammar and privacy
  rules used by task records. Reject detached/empty names, absolute paths,
  traversal, control characters, oversized values, repository roots, and keys
  outside the configured projects root.
- Bind the declared identity before product worktree creation. A subsequent
  `handoffctl run` from any other product root or branch must remain rejected.
  Creation failure must leave a durable binding that can be inspected and
  explicitly cleared only through a separate, locally verified recovery
  operation; silent fallback or automatic rebinding is forbidden.
- Define safe idempotency: replay of the same exact identity at the immediately
  resulting revision may report the already-bound state without another
  revision, while any different identity fails closed.
- Preserve Git and SQLite backend parity, atomic revision/commit behavior,
  generated projections, migration, rollback, snapshots, checkpoints, doctor,
  privacy scanning, and the existing one-active-owner/branch/worktree rules.
- Extend the formal lifecycle model for unbound, bound, conflicting, stale,
  expired, and replayed states. Rejected transitions must stutter and no two
  active tasks may acquire the same nonempty branch or worktree key.
- Document the supported bootstrap sequence: claim the legacy task, bind its
  planned isolated identity at an exact revision, create the worktree through
  `handoffctl run`, and perform all later product/Git commands from that bound
  checkout.

## Acceptance and downstream handoff

The exact candidate must pass focused hostile tests, the complete Coordinator
test/schema/privacy/static suite, and all applicable formal tiers. Locally
verifiable exact-head evidence is sufficient to merge and publish. Hosted CI,
an independent review, cryptographic signatures, and external authentication
may supplement the evidence when available, but none is required to progress.
Then verify every available exact-main workflow.

Publish a development vendor receipt containing the immutable Coordinator
commit/tree and complete manifest identity so ASB-state and asb-tui-state can
adopt it through `sync-development`. Downstream AR-1652 must remain blocked
until its state repository vendors the repair and binds its declared
`repair/ar-1652-record-replay` / `agent-systems-benchmark-ar-1652-record-replay`
identity through the new command. Development authentication, release tagging,
production authorization, external signatures, hosted CI, and independent
review are optional supplementary evidence. Functional fencing, exact identity,
and locally executable verification remain mandatory.
