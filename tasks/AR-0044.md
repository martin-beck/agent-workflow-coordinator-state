## Objective

Introduce the first real upgrade-execution phase without crossing the mutation gate:
validate the selected runtime and authority, acquire the already-proven barrier,
create a durable backend-specific backup, verify its identity, and persist a
session-bound evidence record. The phase must not stage, commit, publish, reopen,
or rollback any runtime.

## Acceptance evidence

- Git and SQLite use one authority-neutral session contract.
- Session identity binds project, attempt, backend, selected runtime, barrier
  revision/fence, and backup digest.
- Preflight rejects stale, ambiguous, aliased, replaced, or unauthenticated state.
- Backup is durable and independently verified before the phase returns success.
- Any failure leaves the coordinator usable and the session write-closed/ambiguous
  as appropriate; no selector or authority mutation is published.
- Hostile tests cover backup destination collisions, authority replacement, WAL/SHM
  changes, process death, fsync/close errors, and forged session identities.
- Formal evidence maps only the bounded phase; implementation refinement remains
  explicitly not-proven and apply/rollback commands remain rejection-only.
