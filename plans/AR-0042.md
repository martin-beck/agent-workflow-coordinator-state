# AR-0042: Bind fixed runtime dispatch to the production consumer

AR-0041 established a descriptor-backed fixed launcher, but only as a reusable
read-only seam. This AR must connect it to one real runtime invocation path without
opening the upgrade mutation gate.

1. Identify the narrowest existing runtime invocation boundary and document its
   caller, selector source, expected identity, and lifecycle ownership.
2. Add a consumer that resolves and admits the selected runtime, prepares the fixed
   command, launches it with the returned descriptor in `pass_fds`, and closes the
   command and admission in all paths.
3. Classify timeout, non-zero exit, spawn failure, descriptor failure, selector
   replacement, manifest replacement, runtime replacement, and child-process death as
   rejection-only outcomes.
4. Add subprocess tests proving the child reads a marker from the selected release;
   prove an adjacent release or caller-supplied path cannot be executed.
5. Add descriptor-leak and cleanup assertions, then run full quality and formal gates.
6. Update the runtime/refinement evidence with exact route and explicit non-claims;
   do not claim Python/TLA refinement or enable upgrade apply/rollback.
