# AR-0020: Correct formal tier policy for merge and advisory exhaustive runs

Correct workflow event selection and protected-check semantics after AR-0019.
The post-merge push path must run the required bounded `pr-fast` model. Weekly
scheduled and manually dispatched full-exhaustive runs remain advisory and use a
several-hour timeout. Release-sensitive changes continue to require the
blocking full-exhaustive tier and exact-head attestation.

Acceptance criteria:

- workflow tests distinguish push/post-merge, ordinary PR, fork PR, release-
  sensitive PR, schedule, and workflow-dispatch tiers;
- `pr-fast` remains a required merge check with explicit model/config and
  truthful non-claims;
- weekly/manual full-exhaustive is advisory only and cannot satisfy merge or
  release evidence;
- release-sensitive publication remains blocking and exact-head bound;
- attestation and branch-protection documentation match the event policy;
- all changes carry signed DCO commits and pass the applicable quality gates.
