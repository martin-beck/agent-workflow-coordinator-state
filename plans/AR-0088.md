# AR-0088 plan: supported active-task worktree binding

1. Reproduce the downstream failure with a fixture task that has a valid live
   claim and empty `branch`/`worktree_key`: claim succeeds and product-checkout
   `run` refuses because no identity is declared.
2. Specify the transition and CLI contract, including exact revision, owner and
   lease admission; bounded branch/key validation; empty-only mutation; conflict
   detection; idempotency; and recovery semantics. Update public schemas and
   embedded documentation before implementation.
3. Implement the transition in the shared authority layer and both Git and
   SQLite backends. Use the ordinary lock, CAS, rollback, commit and projection
   path; do not create a task-file-only special case.
4. Add positive coverage for claim -> bind -> wrapped worktree creation ->
   exact-root/exact-branch run, plus replay of the identical binding.
5. Add hostile coverage for wrong/expired owner, wrong lifecycle, stale
   revision, partial prepopulation, rebind, duplicate active identities,
   traversal/absolute/control/oversized values, detached worktrees, wrong root,
   wrong branch, commit/push/projection failure, and concurrent competing binds.
6. Verify rollback, checkpoint, snapshot, migration, generated views, doctor,
   privacy and size limits. Prove no failure can weaken the existing invocation
   fence or permit a second active task to share an identity.
7. Extend and exhaust the bounded formal models for the new transition and its
   stuttering failure paths. Update vendor closure declarations for every new
   runtime, schema, test, documentation and formal artifact.
8. Run the full deterministic and hosted gates on the exact candidate. Obtain a
   separate-agent defect-first review, repair every finding, and re-run affected
   plus complete gates.
9. Publish one SSH-signed+DCO PR, merge only the independently reviewed tree,
   and watch all exact-main workflows to terminal success.
10. Record the immutable development-vendor commit/tree/manifest receipt for
    downstream adoption. Do not edit downstream task metadata directly and do
    not claim downstream success until the new command has performed the bind.
