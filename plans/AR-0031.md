# AR-0031: Executable upgrade mutation and rollback boundary

Implement the first production-safe mutation slice needed by the correctness-first
upgrade path. The existing Git and SQLite authority adapters intentionally fail
closed for mutation; this AR must make one bounded phase executable without
weakening admission, fencing, backup, selector, or rollback guarantees.

## Required boundaries

- preserve the current fail-closed behavior for unsupported phases;
- implement one explicitly scoped backup/commit/rollback path only after a
  validated barrier, lease, authority identity, and generated operation record;
- prove that every injected failure leaves either the verified old runtime or
  the verified new runtime selected and functional;
- cover Git and SQLite behavior separately where their authority semantics differ;
- add contract, hostile, process-death, and formal correspondence evidence before
  enabling any additional mutation phase;
- require independent review, exact-head hosted gates, post-merge Verify, and
  durable state reconciliation.

The AR does not authorize broad mutation enablement or dispatch of unimplemented
phases. Unsupported operations must continue to fail closed.
