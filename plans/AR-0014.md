# AR-0014: Verified supersession dependency readiness

## Goal

Allow downstream work to proceed past a replaced task without treating an
unfinished or ambiguous replacement as complete.

## Contract

1. Use explicit, schema-versioned successor identity. Never parse
   `next_action`, branch names, commit messages, or issue text as proof.
2. Require the successor to resolve to one task in the same bound project,
   reject self/cyclic/ambiguous references, and require the successor status
   to be `done` with accepted immutable evidence.
3. Bound successor-chain traversal and reject chains that terminate in a
   superseded, missing, malformed, or unfinished task.
4. Apply the identical readiness predicate to Git and SQLite backends and
   expose deterministic blocker text in claim and promotion preflight.

## Implementation and migration

- Extend strict task schema and parser validation without silently accepting
  unknown fields.
- Provide an atomic migration for existing state and leave legacy superseded
  records unsatisfied until explicitly annotated.
- Preserve CAS revisions, leases, lock ordering, bindings, privacy filters,
  generated views, and offline operation.
- Update bounded formal models and review transition invariants.

## Verification

- Positive readiness for one valid done successor and a bounded valid chain.
- Negative readiness for missing, malformed, duplicate, cross-project,
  unfinished, cyclic, stale, self-referential, and overlong chains.
- Git/SQLite parity and migration round trips.
- Concurrent claim/promotion races and exact revision failures.
- Full offline suite, format/lint/type checks, privacy/schema checks, exact
  hosted CI, signed DCO review, immutable release verification, and downstream
  vendor-sync tests after release.

## Dependencies and ownership

AR-0002 supplies the current coordinator contract and backend foundation.
AR-0007/AR-0008 must consume this contract where upgrade/formal transitions
intersect it. Downstream AR-1182 owns vendor synchronization after the signed
release; this AR must not patch downstream vendor files.
