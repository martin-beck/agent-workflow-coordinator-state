# AR-0013: Selector-aware authenticated versioned runtime

Implement the executable runtime boundary required by GitHub issue #28. Keep
the stable bootstrap outside the replaceable release set. It must read only a
bounded release token from a fixed owner-only project location, resolve that
token to an immutable, allowlisted runtime, and bind validation to execution
without permitting path, symlink, hard-link, ownership, mode, manifest,
signature, trust-policy, or selector races. Pass only an independently
validated state root to the selected runtime, which must revalidate permanent
project binding before dispatch.

Acceptance criteria:

- Complete versioned runtime directories can be staged offline while the
  known-good runtime remains intact; existing flat installations stay
  functional and fail closed for upgrade until provisioned.
- A concrete verifier binds the selected release to the allowlisted manifest,
  exact source commit and tag/object identity, signature result, and pinned
  trust-policy digest. Contract hashes alone are never authenticity evidence.
- The selector has bounded syntax/size, owner-only permissions, atomic
  publication, post-rename fsync ambiguity/reconciliation handling, and no
  caller-controlled script or path interpretation.
- Validation rejects symlinks, hard-link aliases, ancestor swaps, path escapes,
  unexpected files/ownership/modes, manifest or signature mismatch, trust-policy
  mismatch, selector/runtime identity changes, and validation-to-exec
  replacement. Define and test the retained-descriptor or equivalent boundary.
- The stable bootstrap is never replaced by an ordinary upgrade. Every normal,
  new-release, rollback, partial-staging, process-death, and ambiguous-fsync
  outcome executes exactly the selected known-good or validated new release, or
  rejects safely without dispatching an unverified runtime.
- Vendoring is redesigned compatibly and without network-required startup or
  executable downstream plugins. The selected runtime revalidates the permanent
  project binding before dispatch.
- End-to-end subprocess tests cover malformed/oversized selectors, symlink and
  hard-link/ancestor swaps, manifest/signature/trust failures,
  validation-to-exec replacement, partial staging, selector rename/fsync
  ambiguity, bootstrap death, and every selector/runtime recovery cross-product.
- Exact-head fresh-clone upgrade/rollback evidence, updated formal refinement
  for selector visibility and crash reconciliation, independent review, signed
  DCO, CI, privacy-safe evidence, and post-publication verification are complete.

Dependencies and ownership:

- AR-0007 owns the executable upgrade barrier, backend adapters, and rollback
  engine that consume this runtime boundary.
- AR-0008 owns the formal refinement and crash/recovery proof obligations for
  this boundary.
- AR-0009 and AR-0010 consume this prerequisite for release integration and
  generated operator/agent runbooks; they do not own it.
- The authoritative upstream issue is
  https://github.com/martin-beck/agent-workflow-coordinator/issues/28.
