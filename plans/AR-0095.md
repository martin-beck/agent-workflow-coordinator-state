# AR-0095: Versioned runtime publication store

Implement the missing, rejection-safe publication boundary beneath the
verified selected-runtime consumer. Add an owner-controlled versioned runtime
store and a concrete trust-policy verifier for immutable staged releases.

The slice may stage and validate complete releases offline, but must not wire
`upgrade apply`, `upgrade rollback`, release dispatch, or any other public
mutation path. Selector publication must remain behind the existing typed
admission seam until the full barrier/restore campaign authorizes it.

Acceptance requires hostile tests for incomplete or unallowlisted staging,
symlink and hard-link aliases, ownership/mode and path-escape failures,
manifest/source/tag identity mismatch, signature and trust-policy failure,
selector/runtime replacement between validation and execution, and process
death or fsync uncertainty. Existing flat installations remain readable and
fail closed for upgrade. Evidence must identify one exact product revision and
pass independent review and hosted checks.
