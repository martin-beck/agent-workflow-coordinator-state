# AR-0096: Durable SQLite WAL/SHM lifecycle reconciliation

## Objective

Implement the missing durable lifecycle record for provisioned SQLite
authority/control WAL and SHM sidecars. Keep ordinary unprovisioned
coordination compatible, reject provisioned lifecycle uncertainty, and leave
upgrade apply, rollback, release, and Dispatch rejection-only.

## Scope

- Define canonical lifecycle identity and digest helpers.
- Record stable authority/control database identity, WAL mode, lifecycle state,
  generation, and sidecar device/inode/size when present.
- Implement explicit `absent -> active -> clean_checkpointed` transitions and
  reject replacement, deletion, impossible generation changes, torn records,
  and transitions without the retained owner-controlled scope.
- Bind reads and writes to the existing typed fence/control-store boundary.
- Add hostile subprocess/process-death and checkpoint/reconciliation tests.

## Non-goals

This AR does not enable public upgrade mutation, selector publication,
rollback, Dispatch, network startup, or any source-to-model refinement claim.
It does not replace the authority database or silently recreate missing
provisioned objects.

## Acceptance evidence

The exact reviewed product head must have focused hostile lifecycle tests,
full repository quality and coverage gates, independent review, hosted checks,
post-merge Verify/Formal, and canonical state reconciliation. Model artifacts
are best-effort guidance only.
