# AR-0087 plan: project-bound task-spec policy and privacy-safe vendor fixtures

## Problem and ownership

Coordinator's task-spec validator currently owns one closed global
`EVIDENCE_CLASSES` set. Downstream state repositories are documented as owning
project-specific task fields and constraints, but they have no supported way
to extend the evidence vocabulary consumed by `render-status`, `doctor`, done
admission, Git/SQLite migration, or lifecycle preflight. A clean official
development sync therefore makes a previously valid downstream state
inoperable unless it patches vendored Coordinator code or rewrites many task
specs.

The same development closure includes exact UUIDv4 literals in upstream test
fixtures. A downstream privacy scanner correctly treats unapproved
session-shaped UUID text as suspicious. Broad path exemptions would weaken the
scanner, and downstream edits would violate immutable vendor identity.

This AR owns the upstream product contract and official vendor closure. It does
not normalize ASB task specs, change ASB workflows, or publish a release/tag.

## Project evidence-policy contract

1. Define one tracked, versioned project task-spec policy file with a strict
   schema and a single additive evidence-class list. Its location and identity
   must be deterministic and repository-bound; it must not come from an
   environment variable, ignored runtime configuration, command argument,
   user home, network response, or current working directory outside the
   bound state root.
2. Preserve the built-in evidence vocabulary when the policy file is absent.
   An extension may add only lowercase hyphenated identifiers within explicit
   count/length/byte bounds. Reject unknown fields, wrong schema versions,
   duplicates, overlap with built-ins, invalid UTF-8/JSON, symlinks,
   non-regular files, escaping paths, oversized input, and permission/identity
   ambiguity. No project may remove or reinterpret a built-in class.
3. Resolve the policy from the already verified project state root and bind it
   consistently into standalone spec validation, task metadata validation,
   done admission, render/status generation, doctor, claim/update/release
   preflight, Git and SQLite backends, migration, rollback/reconciliation, and
   generated-state checks. There must be no validator path that silently uses
   a different vocabulary.
4. Keep diagnostics bounded and public-safe: identify only the policy field and
   validation class, never raw file contents, arbitrary paths, task bodies, or
   external inputs.
5. Add a realistic downstream conformance fixture declaring `hosted`,
   `offline`, `privacy`, `journey`, and `quality`. Prove its existing specs can
   render, pass doctor, transition through exact-revision lifecycle operations,
   record acceptance, migrate Git-to-SQLite-to-Git, and reject removal or
   mutation of the policy after evidence was admitted.
6. Add hostile tests for absent/default behavior, malformed/oversized policy,
   class collisions, stale generated views, dirty/changed policy during a
   transaction, backend parity, migration interruption, failed commit/render/
   replication, and concurrent lifecycle actors. Rejected operations must
   leave tasks, sessions, projections, and authoritative state unchanged.

## Privacy-safe fixtures

1. Remove session-shaped UUID literals from every upstream first-party test
   file that enters the official vendor closure. Construct required UUID test
   values from bounded non-session-shaped fragments at runtime, following the
   existing `guest_seed.py` pattern.
2. Preserve exact positive and hostile UUID semantics. Do not add broad test
   directory exemptions, weaken the UUID scanner, remove invalid-identity
   cases, or hide production source findings.
3. Add a regression that scans an empty clean development-sync destination
   with the strict downstream privacy policy and proves zero unapproved UUID,
   prompt, token, private-path, cache, bytecode, oversized, or raw-transcript
   findings. A deliberately introduced fixture literal must still fail.

## Vendor, formal, and publication requirements

1. Extend schemas, embedded documentation, migrations, tests, and the official
   vendor map so a clean `sync-development` contains the complete policy and
   privacy-safe fixture implementation with exact Git blobs, modes, manifest
   digests, and runtime/formal correspondence.
2. Keep external `unblock` and pause/resume provenance behavior from AR-0085
   and AR-0086 unchanged. Add model/runtime inventory checks only if the new
   policy affects a lifecycle guard; rejected policy loads must stutter with no
   authority mutation.
3. Run source headers, Ruff format/lint, mypy, schemas, privacy and size gates,
   complete unit/fault/race/recovery suites, unchanged 95% branch-aware
   coverage, clean-destination vendor verification, and portable plus
   PR-publication formal tiers.
4. Independently review the exact signed+DCO candidate. Publish a focused PR,
   merge only after every exact-head check succeeds, and verify exact-main
   Verify and Formal workflows after merge.
5. Record the merged commit/tree and complete development-manifest digest for
   ASB-state AR-1747. That downstream must discard its rejected `e863b57`
   candidate, resync through the official path, add only its project policy and
   workflow-owned TLC queue/lock configuration, then rerun all gates. Direct
   downstream vendor edits remain forbidden.

## Definition of done

- Default projects remain byte/behavior compatible with the built-in evidence
  vocabulary and no policy file.
- A bound downstream project can add the five ASB evidence classes without
  patching vendored code, and every validation/admission/backend path uses the
  same policy.
- All hostile policy and atomicity cases fail closed with bounded diagnostics.
- The complete official vendor closure contains no privacy-scanner-shaped
  fixture literals while preserving UUID behavior and scanner strength.
- Full functional, coverage, privacy, vendor, formal, review, PR, merge, and
  post-merge evidence is green and durably recorded.
