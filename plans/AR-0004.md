# AR-0004: Quiescence and upgrade preflight

Define the fail-closed admission boundary: exact release authenticity,
supported runtime, clean and synchronized state, no divergence, no active
leases or wrapped commands, no running reconciliation/publication, valid
binding/backend/vendor state, sufficient disk and scratch capacity, and a
restorable backup destination.

The preflight must not merely report health. It must establish that the system
can remain functional while the upgrade is staged and that reopening work is
safe after success or rollback.
