# AR-0118: Analyze and reduce handoffctl coordinator-lock contention

1. Read the current vendored coordinator guide and map every supported
   handoffctl route to lock acquisition, authority mutation, projection,
   reconciliation, live-observation, and publication phases. Record whether
   each phase is read-only, serialized, or allowed to overlap.
2. Build a fresh isolated project state with several independent worker
   processes and a bounded route mix: snapshots/doctor, claims, heartbeats,
   updates, releases, `handoffctl run`, and reconcile where authorized. Every
   worker must invoke the actual handoffctl command route.
3. Measure acquisition wait, hold duration, timeout/error rate, queue depth,
   successful transitions, and throughput at 1, 2, 4, 8, and higher worker
   counts until the failure/stall regime is reproduced. Emit only bounded,
   privacy-safe aggregates and phase labels.
4. Trace long-held sections and distinguish unavoidable authority serialization
   from avoidable work inside the lock, such as projection rendering, live
   GitHub observation, filesystem scans, or publication. Reproduce crashes,
   worker interruption, stale leases, competing claims, and lock timeouts.
5. Compare safe options: shorter authority critical sections with immutable
   snapshots, SQLite-WAL read concurrency, per-project/per-authority queues,
   coalesced projection work, bounded lock-aware scheduling, or another
   evidence-supported design. Do not trade away linearizability, fencing,
   durable outcomes, or fail-closed ambiguity handling.
6. Implement the selected bounded repair if the evidence supports one;
   otherwise record a justified design and the exact remaining prerequisite.
   Run stress, hostile, property/formal, exact-head review, hosted checks, and
   reconcile the state before release.
