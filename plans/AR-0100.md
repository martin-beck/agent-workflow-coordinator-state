# AR-0100 plan: bounded formal verification tier policy

Create one authoritative tier manifest and validation layer.  Classify every
existing formal invocation, state exactly what each tier proves, and reject
labels that overstate a bounded execution.  Preserve backward-compatible
aliases only where their evidence semantics are identical.  Add focused tests
for schema validation, rendered receipts, and failure classifications.

This is a development-velocity and evidence-clarity change.  It introduces no
human authorization or external verification requirement.
